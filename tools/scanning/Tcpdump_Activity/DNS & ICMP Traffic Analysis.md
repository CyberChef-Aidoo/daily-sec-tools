# 💎 DNS & ICMP Traffic Analysis — Diagnosing a "Destination Port Unreachable" Incident

**Category:** Network Security / Traffic Analysis
**Tools used:** `tcpdump`
**Source:** Coursera — Google Cybersecurity Certificate (Network Security course)

## Scenario

I'm working as a cybersecurity analyst for a company that provides IT services to clients. Customers of one client reported they could not access `www.yummyrecipesforme.com`, seeing a **"destination port unreachable"** error after the page failed to load.

Trying to reproduce the issue myself, I got the same error. To investigate, I used `tcpdump` to capture traffic while attempting to load the page again.

Background on the request flow: the browser first sends a DNS query over **UDP** to a DNS server to resolve the domain name to an IP address. Once it has that IP, it uses it as the destination for an **HTTPS** request to the web server. So a failure early in this chain (DNS) will block everything downstream.

## Packet Capture

```
13:24:32.192571 IP 192.51.100.15.52444 > 203.0.113.2.domain: 35084+ A? yummyrecipesforme.com. (24)
13:24:36.098564 IP 203.0.113.2 > 192.51.100.15: ICMP 203.0.113.2 udp port 53 unreachable, length 254

13:26:32.192571 IP 192.51.100.15.52444 > 203.0.113.2.domain: 35084+ A? yummyrecipesforme.com. (24)
13:27:15.934126 IP 203.0.113.2 > 192.51.100.15: ICMP 203.0.113.2 udp port 53 unreachable, length 320

13:28:32.192571 IP 192.51.100.15.52444 > 203.0.113.2.domain: 35084+ A? yummyrecipesforme.com. (24)
13:28:50.022967 IP 203.0.113.2 > 192.51.100.15: ICMP 203.0.113.2 udp port 53 unreachable, length 150
```

## Analysis

| Field | Value | Meaning |
|---|---|---|
| Source | `192.51.100.15` (my machine, port 52444) | Client sending the DNS query |
| Destination | `203.0.113.2` (`.domain` = port 53) | The DNS server |
| Query type | `A?` | Requesting the IPv4 address record for `yummyrecipesforme.com` |
| Response | `ICMP ... udp port 53 unreachable` | Sent **back from the DNS server itself** |

Three separate query attempts appear (13:24, 13:26, 13:28), each about 2 minutes apart — this is the DNS resolver on my machine retrying after getting no usable answer, which is normal client behavior when a query fails.

**Key detail:** An ICMP "port unreachable" message is generated by a host when a packet arrives at a port with **no service listening on it**. This message is coming from `203.0.113.2` — the DNS server — for `udp port 53`, which is the standard DNS port. That tells us:

- The DNS server host itself **is reachable** on the network (it's alive enough to respond with ICMP).
- However, **nothing is listening on UDP port 53** on that host — meaning the DNS service/daemon is down, misconfigured, or not running.

## Conclusion

**Affected protocol: DNS.**

The web server and HTTPS were never involved in this failure — the browser never got far enough to make an HTTPS request, because it couldn't resolve `yummyrecipesforme.com` to an IP address in the first place. The DNS server is up on the network but its DNS service isn't answering queries on port 53, which is why every client trying to reach the site sees a "destination port unreachable" error.

## Recommended Next Step

Escalate to the team responsible for the DNS server at `203.0.113.2` to check whether the DNS service (e.g. BIND, `named`, or equivalent) is running, correctly configured, and bound to port 53 — rather than treating this as a firewall or web-server issue.

## What I Learned

- How to read `tcpdump` output for DNS (`.domain`) and ICMP traffic.
- What an ICMP "port unreachable" message actually indicates about the *destination* host, not just the network path.
- How to trace a user-facing symptom ("can't load a website") back to the specific protocol and layer responsible, rather than assuming it's the web server at fault.
